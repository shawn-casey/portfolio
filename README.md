# shawncasey.dev, a portfolio built as an Obsidian vault

A single-page site that looks and behaves like [Obsidian](https://obsidian.md): file-tree sidebar,
markdown reading view, computed backlinks, outline + local graph, a full force-directed graph view,
and a quick switcher. The Obsidian shell isn't decoration. It's the honest form of a real 264-note
vault that ran through an internship. See the **About This Site** note.

## Run it

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # static bundle in dist/
npm run preview
```

## Editing content

Every note is a plain markdown file in `src/content/notes/`. Add a file, it appears in the site.
There is no per-note code anywhere.

```markdown
---
id: some-note           # url slug; wiki links resolve to this, the title, or an alias
title: Some Note
folder: Projects        # must be one of SITE.folders in src/content/config.ts
order: 3                # position within the folder in the file explorer
tags: [agents, security]
aliases: [Nickname]     # optional; [[Nickname]] resolves here too
summary: One line, shown on tag-search cards.
hub: true               # optional; `true` = top-level hub, `center` = the home note
---

Body markdown. [[Wiki Links]] and [[Wiki Links|with display text]] work.
```

Supported beyond normal markdown / GFM:

| Syntax | Result |
|---|---|
| `[[Note]]`, `[[Note\|label]]` | Internal link with hover preview; feeds the graph and backlinks |
| `> [!info] Title` | Obsidian callout. Kinds: `info` `note` `tip` `warning` `caution` `danger` `success` `todo` `quote` |
| `![caption](/img/x.webp)` | Figure with caption |
| `![caption\|wide]`, `\|inset`, `\|portrait`, `\|logo` | Figure style variants. `inset` never upscales past the file's own width |
| `{{fingerprint}}`, `{{visits}}` | Live widgets (used by the **Visitor** note) |
| `{{email}}` | Expands to `SITE.gtEmail` as a mailto link |

Single newlines render as line breaks, same as Obsidian's default reading view.

Backlinks, the graph, the outline, tag counts, word counts, and the status bar are all derived at
load time from these files. Nothing is hand-maintained.

### Before publishing

**`src/content/config.ts` → `SITE.gtEmail`** still says `REPLACE-ME@gatech.edu`. It renders as a
visible TODO callout on the Contact note until it's replaced.

The social card at `public/og.png` is generated by `scripts/og.mjs`. Regenerate it if the
tagline or note counts change.

## Images

Source photos live in the parent directory. Three scripts turn them into `public/img/*.webp`:

- `scripts/images.mjs` resizes and converts the main set.
- `scripts/headshot.mjs` flood-fills the studio white background in from the borders. The headshot
  isn't used on the site right now; run this if you want it back.
- `scripts/images-new.mjs` handles the screenshots. It does one **redaction** worth knowing about:
  the scaling diagram has an internal platform name painted over and replaced with "the cloud".
  If that name is actually public, restore it there.

Outputs are committed, so `sharp` is only needed when a photo is added or replaced.

Clicking any figure opens it full size in a lightbox, which is how the two wide screenshots stay
readable in a 664px reading column.

## The visit counter

`api/visits.js` is a serverless function that keeps an **aggregate** count per city. It reads a
coarse city from an edge geo header, increments `city -> integer` in Redis, and discards the IP in
the same request. No IP addresses, timestamps, sessions, user agents, or referrers are stored, so
no individual visit is ever attributable. The reasoning is written up on the **Visitor** note.

- `GET /api/visits` reads the aggregate
- `POST /api/visits` increments this city, then reads (the client posts once per browser session)

Set two environment variables to turn it on:

```
UPSTASH_REDIS_REST_URL
UPSTASH_REDIS_REST_TOKEN
```

Without them, the endpoint answers with your own geo and a zeroed aggregate, and the Visitor note
falls back to a client-side `ipapi.co` lookup for the location line and says plainly that the
counter isn't connected. The site never breaks.

## Deploying

> The live site at [shawnecasey.com](https://shawnecasey.com) is served by GitHub Pages from the
> `main` branch. This branch does not affect it. Pages cannot build a Vite app on its own, so
> promoting this site means either adding an Actions workflow that builds and deploys, or pointing
> the domain at a host that builds for you.

**Vercel** (functions work out of the box, `vercel.json` is included):

```bash
vercel
```

**Netlify / Cloudflare Pages / GitHub Pages**: build command `npm run build`, publish directory
`dist`. Routing is hash-based, so no rewrite rules are needed and it works from a subpath. On
Netlify, move `api/visits.js` to `netlify/functions/visits.js` and add a redirect from
`/api/visits`; on GitHub Pages there are no functions, so the counter stays off and the note
degrades as described above.

## Stack

React 19 · TypeScript · Vite · `d3-force` (canvas-rendered, both graphs) · `react-markdown` +
`remark-gfm` + `remark-breaks`. No CSS framework, no router, no state library.
